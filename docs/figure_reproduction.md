## 2. How each panel was rendered

Common form (run from the repository root, with `$env:PYTHONIOENCODING='utf-8'`):

```
python scripts\figures.py --only <panel> [--data-dir "<raw data dir>"] [--allow-heavy]
```

* `fig1a`, `fig1b`, `fig2`, `fig5` read shipped tables in `results/` and need no raw data.
* `fig3a`, `fig3b`, `fig4` retrain native-categorical XGBoost on AI_RCP_BH, so they need
  `--data-dir "<raw data dir>"`. They ran without problems (the loader reports 10 138 rows and a
  13.2 % mean yield for AI_RCP_BH).
* `fig6a`, `fig6b` are gated as heavy and additionally need a Bayesian-optimisation panel table.

Each panel was rendered **individually** so that the exit code belongs to that panel alone;
stdout/stderr are in `outputs/_figcheck/logs/<panel>.log`.

## 5. The Figure 5 caveat (must not be read as reproducibility)

`scripts/figures.py` carries the first three Fig. 5 bars as **hardcoded literals** in
`PROTOCOLS` (lines 166–170):

```python
PROTOCOLS = [
    ("Random-split CV\n(unseen rows)", 0.766),
    ("Substrate-disjoint CV\n(new substrates)", -0.183),
    ("Ordered CV\n(next round)", -1.235),
]
TRANSFER_MEDIAN_FALLBACK = -1.171
```

The comment above them states that they "were carried over verbatim from the authoring script
`make_figs_v14.py`" and that "the underlying run is NOT in this repository". Consequences:

* **Fig. 5's MATCH is by construction.** The render agrees with the paper image because both
  print the same four literals; it is *not* evidence that the cross-validation pipeline can
  reproduce them. If the constants were wrong, the figure would still "match".
* The fourth bar is not computed either: `results/transfer_check.csv` is absent, so
  `_transfer_median()` returns `TRANSFER_MEDIAN_FALLBACK = -1.171` and the script itself prints
  "cross-dataset median source: the value quoted in the paper".
* Corroborating hazard: the legacy code itself notes, in the ordered-CV block, that a split bug had
  made "section 3.6's -1.17" unreproducible and that the ordered CV is now run on the file's record
  order (`Analysis_all_v16.py:1587-1590`). So even the *method* behind the literal has changed since
  the literal was produced; re-running today would not necessarily give −1.235.

**What would make it real:** ship (or re-run and commit) the AI_RCP_BH cross-validation results —
the per-fold R² of the random, ordered and substrate-disjoint 5-fold splits for XGBoost — and have
`fig5()` read them instead of literals. The frozen pipeline already computes both protocols
(`Analysis_all_v16.py:1555-1625`, `GroupKFold` on `substrate_type_encoded` for the
substrate-disjoint split, `KFold(shuffle=False)` for ordered) and writes them as
"CV R² (ordered folds)" / "CV R² (substrate-disjoint)" in `model_evaluation_metrics.csv`
(`Analysis_all_v16.py:8038`). That table is not in `results/`. Ship it (or the reduced per-dataset
CV table) and wire `fig5` to its XGBoost row, and ship `results/transfer_check.csv` for the fourth
bar (15 transfer R² values, median −1.171). Only then does a Fig. 5 match mean anything. Note that
this also implies the paper should reconcile −1.235 (figure) with the text's protocol description,
and −1.171 (figure) with the text's −1.379 (mean of 15).

## 6. Verdict

**Seven of the nine panels the paper needs can be rendered from this repository (four of them
essentially pixel-for-pixel, three cosmetic-only), two cannot be rendered at all, and one of the
seven — Figure 5 — reproduces only because its numbers are hardcoded constants.**

* Rendered and matching: Fig. 1(a), Fig. 2, Fig. 4, Fig. 5 (Fig. 5 by construction).
* Rendered with cosmetic differences only: Fig. 1(b) (canvas/crop), Fig. 3(a) (missing "(a)"),
  Fig. 3(b) (missing "(b)" + canvas aspect).
* Not rendered: Fig. 6(a) and Fig. 6(b) — the Bayesian-optimisation panel table does not exist in
  the repository and can only be produced by the 5.72 × 10⁶-condition virtual-library/BO path.
* No MISMATCH was found: every panel that rendered agrees with the paper in axis labels and
  ranges, number of series/bars, encoded values, legend text and layout.

**One-line verdict:** the repository reproduces 7 of 9 panels (4 exact, 3 cosmetic-only) but
cannot produce Figures 6(a)/6(b) at all and reproduces Figure 5 only from hardcoded literals, so
it does **not** yet reproduce every figure the paper needs.
